Pi Agent 的更新频率实在是太快了，几乎是隔两天一个版本，但作为我的主力 Agent，我基本还是会扫一眼更新日志里的 New Feature 部分。

今天在看 v1.1 的 New Feature 的时候，发现了这么一条：

> **Program status reporting**: terminals and agent dashboards that support OSC 7501 see whether Pi is working, blocked on a dialog or login, done, or failed. See [Program status](https://github.com/earendil-works/pi/blob/v1.1.0/packages/coding-agent/docs/terminal-setup.md#program-status).

感觉可以用到我现有的工作流上（Ghostty + Tmux + Pi）。

最近出现了不少终端应用，都号称是为 AI Agent 设计的，比如 cmux、zentty、agent-manager 等，在我看来，它们最大的价值在于，并行运行多个 AI Agent 时，可以一眼看到各个 Agent 的状态。既然 Pi 已经可以自己汇报状态了，我应该很容易就能集成进我的工作流。于是，我启动 Pi，给了它一个 Prompt：

> 看下 pi agent 最新的 Program status 能力，看看如何和 tmux 结合使用

Pi (deepseek-light) 很快就给了我一个推荐方案。

![Pi 的推荐方案](/fs/26-10-09-pi-recommendation.png)

看着靠谱，接受方案，一分钟后，我就有了带 Agent 状态展示的 Tmux 状态栏。

![Pi 状态栏](/fs/26-10-09-pi-status-tmux.png)

- 黄色圆点：Agent 正在工作
- 红色方块：Agent 被阻塞，需要用户输入
- 绿色对号：Agent 已完成任务

非常完美。

能随时随地**按需**自定义，就是 Pi 忠实用户最大的乐趣。
